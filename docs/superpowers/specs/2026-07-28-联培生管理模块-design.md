# 联培生管理模块设计

## 背景与目标

### 背景

OmniDesk 现有 `personnel` 模块覆盖在职员工的档案/合同/教育背景/家庭成员等通用信息，但**联培生**（联合培养硕博研究生）的管理诉求完全独立：

- 联培生**不是正式员工**：无劳动合同，签的是"联合培养协议"；补助而非工资
- 有**导师**归属，但导师不参与审批流程
- 每月需填写**月度报告**（工作进展 + 工作亮点）
- **月末考核**：专家组打分 + 出勤考核 + 补助自动计算
- 考核结果分 **A 档 / B 档**（A 档名额硬性限制 ≤ 40%，名额优先）
- 月补助 = 基本额度（硕士 3000 / 博士 6000）× 考核系数 × 出勤比

现有系统**完全没有**联培生相关业务代码（grep 结果：0 命中 attendance/考勤/签到，无 schedule app）。因此需要从零搭建。

### 目标

为 OmniDesk 添加完整的**联培生管理子模块**，覆盖：

1. 联培生档案与导师归属
2. 联培生月度报告（含出勤数据）
3. 月末考核批次（Celery 自动触发 + 手动提前）
4. 专家组打分（独立打分 + 互相不可见）
5. A 档 40% 名额优先算法
6. 月补助自动计算 + 联培生管理员复核 + 联培生可见
7. 联培生管理员独立 Group（与人员 HR 互不重叠）

### 非目标（明确范围外）

- ❌ 考勤系统（打卡/排班）：项目里没有，也不引入
- ❌ 论文/科研成果管理
- ❌ 财务系统对接：补助仅生成记录，不与外部银行/工资系统打通
- ❌ 通知渠道扩展：仅复用站内 `Notification`，不引入邮件/短信/微信

## 数据模型（6 张表）

### 1. `JointStudent` — 联培生扩展表

1:1 关联 `personnel.Personnel`，**不修改 Personnel 主表**。

| 字段 | 类型 | 说明 |
|---|---|---|
| `personnel` | OneToOneField(Personnel, PROTECT) | 关联到 Personnel 主表（必填） |
| `student_type` | CharField(choices=master/phd) | 硕士/博士 |
| `student_id` | CharField(max_length=50, unique=True) | 学号 |
| `enrollment_date` | DateField | 入学日期 |
| `graduation_date` | DateField(null=True) | 毕业日期（未毕业为 NULL） |
| `mentor` | ForeignKey(Personnel, SET_NULL, null=True) | 导师（仅记录身份） |
| `is_active` | BooleanField(default=True) | 是否在读（毕业后置 False） |
| `created_at` | DateTimeField(auto_now_add=True) | |
| `updated_at` | DateTimeField(auto_now=True) | |

**索引**：`('student_type', 'is_active')` 联合索引。

### 2. `MonthlyReport` — 月度报告

| 字段 | 类型 | 说明 |
|---|---|---|
| `joint_student` | ForeignKey(JointStudent, related_name='monthly_reports') | |
| `year` | PositiveSmallIntegerField | 年份 |
| `month` | PositiveSmallIntegerField | 1-12 |
| `work_progress` | TextField | 工作进展 |
| `work_highlights` | TextField | 工作亮点 |
| `attendance_days_actual` | DecimalField(5, 1) | 实际出勤天数 |
| `attendance_days_expected` | DecimalField(5, 1, default=22) | 应出勤天数 |
| `attendance_notes` | TextField(blank=True) | 出勤补充说明 |
| `status` | CharField(choices) | draft/submitted/approved/rejected |
| `submitted_at` | DateTimeField(null=True) | 提交时间 |
| `reviewed_at` | DateTimeField(null=True) | 审核时间 |
| `reviewer` | ForeignKey(CustomUser, null=True, SET_NULL) | 审核人 |
| `reviewer_comment` | TextField(blank=True) | 审核意见 |

**约束**：`unique_together = ('joint_student', 'year', 'month')` — 一人一月一份报告。

**状态机**（同一行记录状态切换，不创建新记录以保持 unique_together）：
```
draft → submitted (联培生提交)
submitted → approved (联培生管理员通过)
submitted → rejected (联培生管理员驳回, 必填 comment)
rejected → draft (联培生修改后重提)
approved → draft (联培生管理员撤回重审, 同一行改状态)
```

### 3. `AssessmentCycle` — 考核批次

每月一批次。

| 字段 | 类型 | 说明 |
|---|---|---|
| `year` | PositiveSmallIntegerField | |
| `month` | PositiveSmallIntegerField | |
| `cycle_start_date` | DateField | 报告提交窗口开始 |
| `cycle_end_date` | DateField | 报告审核截止（专家打分开始） |
| `scoring_deadline` | DateField | 专家打分截止 |
| `status` | CharField(choices) | collecting/scoring/closed/finalized |
| `created_at` | DateTimeField(auto_now_add=True) | |
| `created_by` | ForeignKey(CustomUser, null=True, SET_NULL) | 创建人（手动触发时记录） |
| `trigger_source` | CharField(choices) | auto (Celery) / manual (联培生管理员) |

**约束**：`unique_together = ('year', 'month')` — 一月一批次（Celery 幂等保护）。

**状态机**：
```
[新创建] collecting ──所有专家提交打分──→ closed ──自动算 grade+补助──→ finalized
                       (或 admin 强制)         (status=pending)
                                                   ↓
                                              locked (联培生管理员复核锁定, 联培生可见)
```

### 4. `ExpertScore` — 专家打分

| 字段 | 类型 | 说明 |
|---|---|---|
| `cycle` | ForeignKey(AssessmentCycle, related_name='scores') | |
| `expert` | ForeignKey(CustomUser, related_name='expert_scores') | 限制在 "考核专家组" Group |
| `joint_student` | ForeignKey(JointStudent, related_name='expert_scores') | |
| `score` | DecimalField(5, 2, validators=[Min(0), Max(100)]) | |
| `comment` | TextField(blank=True) | |
| `submitted_at` | DateTimeField() | 提交时间（提交后锁死） |
| `is_locked` | BooleanField(default=True) | 默认锁死，admin 可 `unlock()` |

**约束**：`unique_together = ('cycle', 'expert', 'joint_student')` — 一专家一联培生一周期一分。

**可见性规则**：
- 提交前，专家 A 看不到专家 B 的分数（前端按 expert=self 过滤）
- 提交后，专家 A 仍看不到专家 B 的分数（独立打分，互相不可见）
- 联培生管理员 / admin 可看到所有分数

### 5. `StipendRecord` — 补助记录

每联培生每月一行。

| 字段 | 类型 | 说明 |
|---|---|---|
| `cycle` | ForeignKey(AssessmentCycle, related_name='stipends') | |
| `joint_student` | ForeignKey(JointStudent, related_name='stipends') | |
| `average_score` | DecimalField(5, 2) | 该专家均分 |
| `rank_in_cycle` | PositiveSmallIntegerField | 周期内排名（用于 A 档分配） |
| `grade` | CharField(choices=A/B) | A 档 / B 档 |
| `base_amount` | DecimalField(10, 2) | 基本额度（硕士 3000，博士 6000） |
| `grade_coefficient` | DecimalField(4, 2) | 1.00 / 0.80 |
| `attendance_ratio` | DecimalField(5, 2) | 实出勤/应出勤（上限 1.0） |
| `final_amount` | DecimalField(10, 2) | 最终补助金额 |
| `status` | CharField(choices) | pending/locked |
| `locked_at` | DateTimeField(null=True) | 锁定时间 |
| `locked_by` | ForeignKey(CustomUser, null=True, SET_NULL) | 锁定操作人 |
| `notes` | TextField(blank=True) | 复核备注 |

**约束**：`unique_together = ('cycle', 'joint_student')` — 一周期一联培生一行。

**公式**：
```
final_amount = base_amount × grade_coefficient × attendance_ratio
其中：
  base_amount: student_type=master → 3000；phd → 6000
  grade_coefficient: A → 1.00；B → 0.80
  attendance_ratio: min(attendance_days_actual / attendance_days_expected, 1.0)
```

### 6. 决策：不引入 `AttendanceRecord` 子表

出勤明细（每日打卡）暂不实现，月度出勤汇总直接存在 `MonthlyReport` 上。未来需要"逐日打卡"再扩展。

## 业务规则算法

### A 档名额优先算法（名额 ≤ 40%）

```python
# services/grading.py

def assign_grades(cycle: AssessmentCycle) -> list[dict]:
    """根据专家打分的均分给本月联培生分 A/B 档（名额硬性 ≤ 40%）。
    
    Returns: 列表，每项包含 {js_id, rank, grade, avg_score}
    """
    # 1. 找本月所有已审核通过的月度报告对应的联培生
    approved_students = MonthlyReport.objects.filter(
        cycle=cycle, status=APPROVED
    ).values_list('joint_student_id', flat=True).distinct()
    
    # 2. 计算每位联培生的专家均分
    student_scores = []
    for js_id in approved_students:
        avg = ExpertScore.objects.filter(
            cycle=cycle, joint_student_id=js_id
        ).aggregate(avg=Avg('score'))['avg']
        if avg is None:
            continue  # 没专家打分则跳过
        student_scores.append((js_id, avg))
    
    if not student_scores:
        return []
    
    # 3. 按分数降序排序（分数相同时按 joint_student.id 升序保证稳定）
    student_scores.sort(key=lambda x: (-x[1], x[0]))
    
    # 4. 前 40% 为 A 档，其余 B 档（名额硬限制，不允许超过）
    total = len(student_scores)
    a_count = math.floor(total * 0.4)  # 向下取整
    
    records = []
    for rank, (js_id, avg_score) in enumerate(student_scores, start=1):
        grade = 'A' if rank <= a_count else 'B'
        records.append({'js_id': js_id, 'rank': rank, 'grade': grade, 'avg_score': avg_score})
    
    return records
```

**边界 case**：
- 总人数 ≤ 2：a_count = 0 → 全部 B 档（避免给单人硬升 A）
- 总人数 = 3：a_count = 1 → 1 人 A 档，2 人 B 档
- 总人数 = 10：a_count = 4 → 4 人 A 档，6 人 B 档
- 专家打分人数不足（< 2 人）：跳过该联培生，不计入 A/B 档

### 补助计算（最终公式）

```python
# services/stipend.py

def compute_stipend(js: JointStudent, grade: str, attendance_actual: Decimal, attendance_expected: Decimal) -> Decimal:
    base = Decimal('3000') if js.student_type == 'master' else Decimal('6000')
    grade_coef = Decimal('1.00') if grade == 'A' else Decimal('0.80')
    
    if attendance_expected <= 0:
        attendance_ratio = Decimal('1.00')  # 防御：应出勤 0 时按满勤
    else:
        attendance_ratio = min(attendance_actual / attendance_expected, Decimal('1.00'))
    
    return (base * grade_coef * attendance_ratio).quantize(Decimal('0.01'))
```

### 批次生命周期（services/cycle.py）

```python
def create_cycle(year, month, trigger_source='auto', creator=None) -> AssessmentCycle:
    """幂等创建考核批次。"""
    cycle, created = AssessmentCycle.objects.get_or_create(
        year=year, month=month,
        defaults={
            'cycle_start_date': date(year, month, 1),
            'cycle_end_date': date(year, month, 25),
            'scoring_deadline': date(year, month, 28),
            'status': 'collecting',
            'trigger_source': trigger_source,
            'created_by': creator,
        }
    )
    if not created:
        logger.info(f"周期 {year}-{month:02d} 已存在，跳过")
    else:
        notify_experts(cycle)
    return cycle


def close_cycle(cycle: AssessmentCycle) -> None:
    """批次截止：状态 collecting → closed，自动算 grade 和 stipend（status=pending）。"""
    # 1. 更新状态
    cycle.status = 'closed'
    cycle.save()

    # 2. 算 grade（A 档名额优先）
    grade_records = assign_grades(cycle)

    if not grade_records:
        logger.warning(f"周期 {cycle.year}-{cycle.month:02d} 无任何打分记录，无补助生成")
        return

    # 3. 创建 StipendRecord（status=PENDING），复用 compute_stipend() 计算 final_amount
    for gr in grade_records:
        js = JointStudent.objects.get(id=gr['js_id'])
        report = MonthlyReport.objects.get(
            joint_student=js, year=cycle.year, month=cycle.month
        )
        final_amount = compute_stipend(
            js, gr['grade'],
            report.attendance_days_actual,
            report.attendance_days_expected,
        )
        # attendance_ratio 由 compute_stipend 内部计算（防御应出勤 0），这里重复一次供前端展示
        if report.attendance_days_expected <= 0:
            att_ratio = Decimal('1.00')
        else:
            att_ratio = min(
                report.attendance_days_actual / report.attendance_days_expected,
                Decimal('1.00'),
            )
        StipendRecord.objects.create(
            cycle=cycle,
            joint_student=js,
            average_score=gr['avg_score'],
            rank_in_cycle=gr['rank'],
            grade=gr['grade'],
            base_amount=Decimal('3000') if js.student_type == 'master' else Decimal('6000'),
            grade_coefficient=Decimal('1.00') if gr['grade'] == 'A' else Decimal('0.80'),
            attendance_ratio=att_ratio,
            final_amount=final_amount,
            status='pending',
        )

    # 4. 通知联培生管理员复核
    notify_managers_to_review_stipends(cycle)
```

## 权限模型

### Django Groups

| Group | 职责 | 创建方式 |
|---|---|---|
| `考核专家组` | 专家打分 | migration data migration 创建空 Group，admin 手动加成员 |
| `联培生管理员` | 模块日常管理（审核报告/触发批次/复核补助） | migration data migration 创建 |
| 动态 Group | 由 JointStudent 信号自动创建（每位联培生/导师一个 Group，控制对象级访问） | signal |

**关键决策**：联培生管理员是**独立 Group**，与现有"人员 HR" Group **互不重叠**。

### DRF 权限类（permissions.py）

```python
class IsJointStudentManagerOrReadOnly(BasePermission):
    """联培生管理员可写, 认证用户可读。"""
    def has_permission(self, request, view):
        if request.method in SAFE_METHODS:
            return request.user.is_authenticated
        return request.user.groups.filter(name='联培生管理员').exists()


class IsExpertGroupMember(BasePermission):
    """必须是 考核专家组 成员。"""
    def has_permission(self, request, view):
        return request.user.groups.filter(name='考核专家组').exists()


class IsOwnerOrReadOnlyForStudent(BasePermission):
    """联培生只能修改自己的月度报告。"""
    def has_object_permission(self, request, view, obj):
        if request.method in SAFE_METHODS:
            return True
        return obj.joint_student.personnel.user_account == request.user
```

## Celery 任务

### 自动触发（Beat 调度）

```python
# tasks.py

@shared_task
def check_and_create_assessment_cycle(year=None, month=None, trigger_source='auto', creator=None):
    """每月定时跑，检查并创建本月批次（幂等）。"""
    now = timezone.now()
    year = year or now.year
    month = month or now.month
    cycle = services.cycle.create_cycle(year, month, trigger_source=trigger_source, creator=creator)
    return {'cycle_id': cycle.id, 'status': cycle.status}
```

```python
# settings.py

}
```

### 手动触发（联培生管理员 UI）

```python
class TriggerCycleView(APIView):
    permission_classes = [IsAuthenticated, IsJointStudentManager]
    
    def post(self, request):
        today = date.today()
        task = check_and_create_assessment_cycle.delay(
            year=today.year, month=today.month,
            trigger_source='manual', creator=request.user,
        )
        return Response({'task_id': task.id}, status=202)
```

### Management command（运维备选）

```python
# management/commands/create_assessment_cycle.py
class Command(BaseCommand):
    def add_arguments(self, parser):
        parser.add_argument('--year', type=int)
        parser.add_argument('--month', type=int)
        parser.add_argument('--source', type=str, default='manual')
    
    def handle(self, *args, **opts):
        year = opts.get('year') or date.today().year
        month = opts.get('month') or date.today().month
        cycle = services.cycle.create_cycle(year, month, trigger_source=opts['source'])
        self.stdout.write(self.style.SUCCESS(f"批次 {year}-{month:02d} 创建成功: {cycle.id}"))
```

## 风险评估与依赖

### 风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| 联培生管理员创建 JointStudent 时跨 app 写 Personnel | 中 | 联培生模块只**新增** JointStudent 行，**不修改** Personnel（PROTECT on_delete） |
| Celery 自动触发与手动触发并发冲突 | 中 | `unique_together(year, month)` 数据库级兜底；get_or_create 幂等 |
| 专家打分后 admin 解锁导致分数被覆盖 | 低 | 解锁动作必须 admin 角色；记录 `submitted_at` 历史 |
| 出勤数据联培生虚报 | 中 | 必须经联培生管理员审核才能进入批次 |
| A 档名额 40% 算法边界（人数 < 3） | 低 | `math.floor(n*0.4)` 兜底，< 3 全部 B 档 |
| 浏览器兼容（Windows 7 + Chrome 109） | 低 | 复用现有 Vite 配置；只用 Ant Design 5 + 原生 JS |

## 设计哲学小结

- **最小爆炸半径**：Personnel 主表 zero migration，新 app `joint_students`
- **职责单一**：联培生管理员 vs 人员 HR 完全分离
- **幂等保护**：批次按 (year, month) 唯一，自动+手动触发不冲突
- **透明可控**：补助状态机 pending → locked，联培生管理员复核锁定后才公开
- **80%+ 覆盖率**：模型/服务/API/任务各层都有边界 case 测试
