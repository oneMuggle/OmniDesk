## 2. 只读 fanout

### 2.1 现状

- `ExecutionMode.FANOUT` 已在 TaskPacket 中定义，但执行器直接返回 `rejected`。
- Supervisor 在 LLM 产出 fanout 计划时抛出 `ValidationError`，任务创建直接失败，用户看到的是报错。
- SubTaskRunner 在子任务中会把用户有权使用的**全部**工具交给 LLM，包括写工具。

### 2.2 设计

**分层并行。** 按依赖把子任务分层，同一层的子任务互不依赖，并行执行；层与层之间串行；最后执行 `final_synthesis`。
- 依赖取 `depends_on` 与 `inputs` 中 `$subtask_id` 引用的并集。即使 LLM 漏写 `depends_on`，也不会在引用的数据还没产出时就开跑。
- 每层开跑前沿用 pipeline 的跳过逻辑：暂停、取消、恢复时跳过已完成的子任务、Token 预算耗尽、依赖失败（按 `failure_mode` 处理）。
- 结果按计划中的顺序收集，保证事件和持久化的顺序是确定的。

**只读约束，强制执行，不靠提示词。** fanout 子任务使用独立的 SubTaskRunner，并设置 `read_only_tools=True`：
- 交给 LLM 的工具 schema 只含 `risk_level == "read"` 的工具（`ToolRegistry.get_openai_tools(user, read_only=True)`）。
- 即使 LLM 仍然调用了写工具，`_execute_tool` 也会直接返回 `{"error": "tool_not_allowed_in_fanout"}`，不会执行。
- `final_synthesis` 在 fanout 任务中同样使用只读 runner。
- 因此 fanout 路径不会产生待确认的写操作。需要写入的任务仍然走 pipeline，每一步单独确认。

**线程安全。**
- 每个子任务使用独立的 SubTaskRunner 实例，避免共享 `_pending_confirmation` 和计数器。
- `EventBus.emit` 和 `PersistentEventBus.emit` 加实例级锁，保证事件序号不乱。
- `SharedContext.consume_tokens` 加锁。
- 子任务结果的持久化和产物写入都在主线程中按顺序完成。
- 工作线程结束时关闭本线程的数据库连接（`connections.close_all()` 只作用于当前线程）。
- 并发数为 1 或本层只有一个子任务时不开线程，直接在当前线程执行。测试环境使用 SQLite 内存库，也依赖这一点。

**预算。** 同一层并行时可能略微超出 Token 预算：每个子任务开跑前都会检查预算，但同一层内已经开跑的子任务不会被中途打断。这一点写进文档。

**恢复。** 暂停后恢复时，执行器按模式分派：fanout 走分层执行，并跳过已完成的子任务。原来"恢复仅支持 PIPELINE"的限制，放宽为 PIPELINE / FANOUT 两种模式。

**Supervisor。**
- 接受 fanout，只拒绝 hierarchical。
- 在 prompt 中说明使用条件：子任务彼此独立、只查询不修改时用 fanout；涉及修改的任务必须用 pipeline。

### 2.3 测试

- 分层：无依赖时为一层；A→B 时为两层；`inputs` 中的引用会被当作依赖。
- 并行：用模拟的 runner 记录线程并加入延时，验证同一层确实并发执行，且并发数不超过上限；并发数为 1 时在当前线程执行。
- 只读：schema 调用带 `read_only=True`；调用写工具时返回 `tool_not_allowed_in_fanout`，且工具没有被执行。
- 依赖失败时按 `skip` / `abort` 处理；暂停后后续层被跳过；fanout 任务可以从 checkpoint 恢复。
- Supervisor 接受 fanout，拒绝 hierarchical。
- 原 `test_fanout_rejection.py` 改为只断言 hierarchical 被拒绝。

## 3. AI 入口收敛

### 3.1 现状（11 个页面）

- 主应用：`/smart-assistant`、`/smart-assistant/tasks`、`/smart-assistant/stats`、`/knowledge-base`、`/ragflow-chat`、`/ai-showcase`、`/dify-apps`（含 `/dify-apps/:appId`）、`/office-assistant`、`/file-analysis`。
- 控制台：`/control-panel/smart-assistant/audit`、`/control-panel/ai-apps`。
- 侧边栏「AI 助手」下有 7 个入口。

### 3.2 目标结构

| 入口 | 新路由 | 内容 |
|---|---|---|
| 智能助手 | `/smart-assistant` | 标签：对话（默认）/ 任务 `/smart-assistant/tasks` / 应用 `/smart-assistant/apps` |
| 应用（智能助手下） | `/smart-assistant/apps/<应用>` | `dify`（含 `/smart-assistant/apps/dify/:appId`）、`ragflow`、`office`、`file-analysis`；未知应用回到应用列表 |
| 知识库 | `/knowledge-base` | 不变 |
| AI 管理（控制台） | `/control-panel/ai` | 标签：统计 `/control-panel/ai/stats`、审计 `/control-panel/ai/audit`、应用配置 `/control-panel/ai/apps` |

**旧地址重定向**（`<Navigate replace>`，保留查询参数）：

| 旧地址 | 新地址 |
|---|---|
| `/smart-assistant/stats` | `/control-panel/ai/stats` |
| `/ragflow-chat` | `/smart-assistant/apps/ragflow` |
| `/dify-apps` | `/smart-assistant/apps/dify` |
| `/dify-apps/:appId` | `/smart-assistant/apps/dify/:appId` |
| `/office-assistant` | `/smart-assistant/apps/office` |
| `/file-analysis` | `/smart-assistant/apps/file-analysis` |
| `/ai-showcase` | `/smart-assistant` |
| `/control-panel/smart-assistant/audit` | `/control-panel/ai/audit` |
| `/control-panel/ai-apps` | `/control-panel/ai/apps` |

**权限不变。**
- 统计接口本身就是 `IsSmartAssistantAdmin`，移到控制台后与后端权限一致。
- 审计、应用配置沿用 `ADMIN_ONLY`；AI 管理页按标签分别校验，看不到的标签不显示。
- `adminRoutePermissions` 新增 `ai`、`ai/stats`、`ai/audit`、`ai/apps`，每个新 key 还接受对应的旧页面路径授权（如 `ai/audit` 接受 `/control-panel/smart-assistant/audit`）。这样已通过用户组页面授权访问旧页面的人，迁移后不会失去访问。旧 key 保留给重定向路由的守卫使用。
- 控制台首页候选列表中，`smart-assistant/audit` 和 `ai-apps` 替换为 `ai`。

### 3.3 组件

- `SmartAssistantLayout`：顶部为标签栏，内容区用 `<Outlet />`。对话页仍然使用现有的 `SmartChatPage`。标签和应用清单统一放在 `layout/assistantNav.js`。
- `AssistantAppsPage`：应用卡片网格（Dify / Ragflow / Office / 文件分析）。每个应用是一条显式子路由，挂载原页面组件；`apps/*` 兜底回到应用列表。
- `AiManagementLayout`（控制台）：标签栏 + `<Outlet />`，按权限过滤标签；`AiManagementIndex` 跳到第一个有权限的标签。
- `LegacyRedirect`：旧地址重定向，自动填充路由参数，并保留查询参数和 hash。
- 侧边栏「AI 助手」只保留：智能助手、知识库。智能助手菜单项设置 `matchPrefix`，在子标签页上也保持高亮。控制台菜单中「Agent 审计」「AI 应用管理」合并为「AI 管理」。
- `/ai-showcase` 页面组件、样式和测试一并删除。用户手册 08 / 22 / 23 / 24 / 25 同步更新了地址。
- 页面内原有的 `navigate('/dify-apps/…')` 等写死的链接改为新地址，避免多跳一次。
- S2-1 的「完整页隐藏悬浮按钮」规则扩展到 `/smart-assistant/*`。

### 3.4 测试

- 每条重定向：旧地址渲染后跳到新地址，查询参数保留。
- 智能助手标签：默认为对话，切换标签会改变路由；应用列表可进入各应用；未知 appKey 回到列表。
- AI 管理：管理员能看到三个标签；无权限时不显示对应标签。
- 侧边栏：AI 助手下只有两个入口。
- 抽屉：`/smart-assistant/apps/ragflow` 下也隐藏悬浮按钮。

## 4. 不做

- hierarchical 模式：继续拒绝。
- 原生函数调用按组开放（§5.2 第 3 条）：需要先有评估集和模型准入条件，留到 S3 之后。
- 改动 Dify / Ragflow / Office 页面内部：只改挂载位置和写死的链接。

## 5. 退出条件

- 后端全量测试通过，覆盖率不下降；前端 lint 和 Jest 全绿；CI 10 项全绿。
- fanout 路径无法执行写工具（有测试证明）。
- 所有旧地址都能跳到新位置；已有的用户组页面授权迁移后仍然有效。唯一的收紧是统计页：前端以前对所有登录用户开放（后端本来就要求管理员），现在前端也要求管理员或旧页面授权。
