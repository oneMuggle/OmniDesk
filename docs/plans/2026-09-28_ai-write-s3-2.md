# S3-2：公告草稿 + 试验日程创建

> 依据：`docs/mcp-ai-orchestration-plan.md` §5.3 第 3、5 项；`docs/plans/2026-09-27_ai-write-s3-1.md`（统一流程已在 S3-1 完成）。分支 `feat/ai-write-s3-2`，基于 main 91f6aa8c（S3-1 合并后）。

## 0. 已确认的决定

| 问题 | 决定 |
|---|---|
| 公告 | 公告模型新增「草稿」状态；AI 只能起草，发布一律由人在公告管理页点「发布」 |
| 谁能让 AI 起草公告 | 仅管理员 / HR（Admin、Manager 组或超级用户），与现有公告写权限一致；草稿也只有他们能看到 |
| 日程 | 做试验日程（Trial）创建 |
| 试验时段冲突 | 确认卡片上提示设备或责任人的时段冲突，但允许确认（页面接口本身不检查冲突） |
| 公告页面改动 | 只在公告管理页加「状态」列和「发布」按钮；页面新建公告仍直接发布，行为不变 |

## 1. 现状

- `events.Announcement` 没有状态字段。页面新建即发布，`post_save` 信号立刻给全体用户发通知（作者本人除外）。
- 公告接口 `events/announcements/` 使用 `IsAdminOrManagerOrReadOnly`：所有登录用户可读，管理员 / HR 可写。公告读取入口有：公告页、公告管理页、Dashboard「最新公告」。现有 AI 工具 `announcement_query` 读的是交流区帖子，不读 `events.Announcement`。
- `events.Trial` 包含时间段（TimeSlot）、设备、责任人（Personnel）和状态。页面创建权限同样是管理员 / HR，不检查任何冲突。`Trial.version` 用于页面编辑时的并发校验。

## 2. 公告草稿

### 2.1 模型（迁移 `events/0006`）

- 新增 `status`：`draft` / `published`，默认 `published`，加索引。已有数据和页面新建的公告都视为已发布。
- 新增 `published_at`（可空）。迁移时把已有数据回填为 `created_at`。`save()` 在状态为 `published` 且 `published_at` 为空时自动补上当前时间。

### 2.2 通知

- 把给全体用户发通知的逻辑抽成 `notify_announcement_published(announcement)`。
- 信号只在「新建且已发布」时调用它，所以草稿不会发通知。
- 发布接口在状态从草稿变为已发布时调用一次。

### 2.3 接口

- **列表默认只返回已发布的公告**。管理员 / HR 带 `?include_drafts=1` 时才包含草稿，只有公告管理页这样调用。公告页不变。
- **详情**：管理员 / HR 能看到草稿（编辑页要用）；其他人访问草稿返回 404。
- **`POST events/announcements/{id}/publish/`**：仅管理员 / HR。用 `filter(status=draft).update(...)` 做条件更新；如果已经发布，返回 409，避免重复发布、重复通知。成功后发通知。
- 序列化器新增只读的 `status` 和 `published_at`。页面 PATCH 不能改状态，发布只能走 `publish` 接口。
- **Dashboard「最新公告」**：只取已发布的公告，按 `published_at` 倒序。

### 2.4 AI 工具 `announcement_draft_create`

- 放在 communication 工具集（该工具集的路由已包含 `/announcements`）。
- 注册参数：`required_permission=LOGIN_ONLY`，由工具内部检查是否为管理员 / HR（与合规工具的做法一致）；`DataScope.MODULE`；`ConfirmPolicy.USER`；`ROLLBACK_AGENT_WRITE_LOG`。
- 参数：`title` 和 `content`。用户只给了主题时，由模型（原生调用时的主模型，或抽取模型）写出正文。
- **dry_run**：
  - 校验权限，以及标题 1–200 字、正文不为空。
  - 预览：action「起草公告」，target「公告草稿：标题」，changes 为标题和正文（公开时截到 120 字），权限来源「管理员」或「HR」，可撤销。
  - 在 `warnings` 里写明：「保存为草稿，不会通知任何人；需在公告管理页发布」。
- **confirm**：重新校验权限，创建 `status=draft`、`author=当前用户` 的公告，写日志（create）。
- **撤销**：草稿仍存在、仍是草稿、标题和正文没被改过时删除；已发布或已修改时返回 409，并提示到公告管理页处理。撤销时同样重新校验权限。

## 3. 试验日程创建 `trial_create`

- 放在 schedule 工具集。权限与页面一致，要求管理员 / HR，由工具内部检查。注册参数：`DataScope.MODULE`、`ConfirmPolicy.USER`、`ROLLBACK_AGENT_WRITE_LOG`。
- 参数：
  - `title`（必填）、`client`、`description`
  - `time_slots`：`[{start_time, end_time, description?}]`，至少 1 段、最多 10 段。
    - 结构化参数抽取目前只支持扁平 JSON，因此也接受 `start_time` / `end_time` 单段写法。
  - `responsible_persons`：姓名列表；`equipments`：设备名称列表。
- **dry_run**：
  - 解析时间：结束必须晚于开始，同一试验的各段不能互相重叠。
  - 按姓名精确匹配人员：找不到或有重名时失败，并列出候选。
  - 按名称匹配设备：先精确匹配，再做唯一的模糊匹配。
  - **冲突提示（不阻止确认）**：找出与各时间段重叠、状态不是「已取消 / 已完成」、且与本次共用设备或责任人的其他试验，最多列 5 条。写入 `warnings`，同时计入预览的冲突数量。
  - 预览：action「创建试验日程」，target「试验：标题」；changes 包括客户单位、时间段、责任人、设备；items 列出各时间段。
- **confirm**：
  - 重新校验权限，按存下的 ID 重新读取人员和设备；如果有被删除的，返回 `stale_confirmation`。
  - 在事务中创建 Trial、TimeSlot 和多对多关系，并调用 `update_time_range()`。
  - 写日志（create），after 为快照：标题、客户单位、描述、状态、版本、时间段、人员 ID、设备 ID。
  - 返回结果时再计算一次冲突数，写进结果文案。
- **撤销**：试验仍存在、当前快照与 after 一致（没人在页面上改过）、仍有权限时，删除该试验（时间段级联删除）；否则返回 409。

## 4. 通用补充

- **预览新增 `warnings`**（字符串列表）：`build_preview(warnings=...)`；`public_preview` 白名单加入该字段，最多 5 条、每条截到 120 字。前端确认卡用橙色提示框显示。
- `REVERT_HANDLERS` 登记 `events.Announcement` 和 `events.Trial`。

## 5. 前端

- `WriteConfirmCard`：显示 `warnings`。
- **公告管理页**：
  - 列表请求带 `include_drafts=1`；新增「状态」列（草稿 / 已发布）。
  - 草稿行显示「发布」按钮：确认后调用 `publish`，再刷新列表；遇到 409 时提示「已发布」。
  - 日期列显示发布时间，草稿显示「—」。

## 6. 测试

- **公告模型、接口与通知**：
  - 草稿不发通知，发布时发一次，重复发布返回 409。
  - 普通用户在列表和详情里都看不到草稿；管理员 / HR 带参数才能看到。
  - Dashboard 不显示草稿；页面 PATCH 改不了状态；迁移回填 `published_at`。
- **两个工具**：批准、拒绝、重复提交、取消后再确认、撤销、撤销冲突（草稿已发布或已修改、试验已修改）、越权（普通用户）、参数错误（时间倒置、时段重叠、重名人员、未知设备）、冲突提示出现在预览中但仍可确认。
- **前端**：确认卡显示 warnings；公告管理页的状态列、发布按钮、409 提示。
- 能力目录更新为 34 个工具。

## 7. 不做

- 页面新建公告时「存为草稿」。
- 普通员工起草、审核流。
- AI 发布公告，以及 AI 修改或删除试验。
- 试验冲突的硬拦截；页面接口的冲突检查。

## 9. 实施记录

- 公告迁移为手写的 `events/0006_announcement_status_published_at.py`，包含回填 `published_at = created_at`；`makemigrations --check` 无新增。
- 默认排序改为「草稿（无发布时间）在前，其余按发布时间倒序」，用 `F("published_at").desc(nulls_first=True)`，兼容 SQLite 和 PostgreSQL。
- `privileged_source` 放在 `write_base`，两个工具共用：超级管理员 / 管理员 / HR（经理组）。

- 用户手册 06 原先写的“发布前可保存为草稿或预发布”与实际不符，已改为：页面新建即发布，草稿只能由助手起草。
