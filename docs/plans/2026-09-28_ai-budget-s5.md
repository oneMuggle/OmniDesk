# AI 预算与配额（方案 5.6）：全量计量、按用户 / 用户组 / 应用设上限、两级降级

> 依据：`docs/mcp-ai-orchestration-plan.md` §5.6「预算和配额：按用户、应用、数字员工统计每日 token 和调用次数，超额后降级为只读或排队；流式对话回填成本」，以及 G6「只有上下文长度上限，没有 token 预算或配额」。
> 分支 `feat/ai-budget-s5`，基于 main d184d50b（S4-2 合并后）。

## 0. 已确认的决定

| 问题 | 决定 |
|---|---|
| 超额后怎么降级 | **两级**：到软上限（默认 80%）降为只读，暂停写操作、多步复杂任务和办公文档生成，普通查询照常；到硬上限当天停用 LLM，并提示额度已用完。页面其他功能不受影响 |
| 默认额度 | **只统计、不限制**：所有上限默认 0（不限），管理员看过实际用量后再设 |
| 上限维度 | 全员默认 + **用户组** + 个人覆盖（个人优先于组）+ 每个 AI 应用的每日总量；数字员工沿用 S4-1 的配额 |

## 1. 现状

- 所有 LLM 调用都经过 `llm_service.router.LLMRouter`（`generate` / `generate_with_tools`），分布在 24 个文件里：
  - 智能助手：意图、工具轮、规划、上下文摘要、抽取器、回答生成、多 Agent 任务；
  - 办公助手、文件处理、数字员工。
  - 例外：`documents` 的合规报告抽取直连 `OllamaClient`，不经过路由。
- **只有非流式对话的最后一次调用**把 token 记进 AgentLog。中间调用、流式对话（`estimated_cost=None`）、办公助手、文件处理和数字员工都没有计量。
- 非流式响应有 `usage`，路由会补上 `estimated_cost`（按端点的 `cost_per_1k_tokens` 计算）；流式解析直接丢弃 usage。
- 现有写工具钩子链：`ConfirmationHook`（优先级 20）、`RateLimitHook`（优先级 25，Reject `rate_limit_exceeded`）。三条执行路径（原生调用、旧 JSON、流式）都已处理「非确认类 Reject」：直接阻断，并返回错误码和提示。
- `ToolContext.task_proposal_allowed=False` 时，complex_task 不出任务计划卡。

## 2. 模型（`smart_assistant` 迁移 0023、0024）

**`LlmUsageDaily`**：每日汇总，唯一键为 `(date, user, app_name, staff_key)`。

| 字段 | 说明 |
|---|---|
| `date` | 本地日期（Asia/Shanghai） |
| `user` | 发起用户；数字员工和无法归属的调用为空 |
| `app_name` | 路由的 app（smart_assistant / office_assistant / file_processing / documents） |
| `staff_key` | 数字员工角色，为空表示不是数字员工 |
| `calls`、`failed_calls` | 成功调用次数、失败调用次数 |
| `prompt_tokens`、`completion_tokens`、`total_tokens` | token |
| `estimated_calls` | 其中没有返回 usage、按字数估算的次数 |
| `estimated_cost` | 预估费用（端点配置了单价时） |

- 不按次记明细。行数约为「用户数 × 应用数 × 天数」，统计和拦截都很快。

**`LlmBudgetPolicy`**：上限配置。

| 字段 | 说明 |
|---|---|
| `scope` | `default`（全员默认，仅一条）/ `group` / `user` / `app` |
| `group`、`user`、`app_name` | 对应作用对象，各自唯一 |
| `daily_token_limit`、`daily_call_limit` | 0 = 不限 |
| `soft_limit_percent` | 只读取全员默认那条上的值，默认 80，所有上限共用 |
| `note`、`updated_by`、`updated_at` | 备注和修改记录 |

- 数据迁移建出全员默认这一条，上限为 0 / 0，软上限 80%。

**用户上限怎么确定**
1. 有个人覆盖时用个人覆盖；覆盖里填 0 表示明确不限。
2. 否则看所在用户组的配置；属于多个组时，每一项取最宽松的值（0 最宽松）。
3. 都没有时用全员默认。
- 用户当日用量 = 该用户在所有应用上的合计（不含数字员工）。
- 应用当日用量 = 该应用的全部调用，包括数字员工。

**状态计算**：对每一项设了上限的值：
- 用量 ≥ 上限 → **blocked**；
- 用量 ≥ 软上限比例 → **readonly**；
- 否则 **ok**。
- 最终状态取用户状态和应用状态中最严重的一个。

## 3. 计量（`llm_service/metering.py` + `smart_assistant/budget/`）

**归属**：用 `usage_scope(user=…, staff_key=…)`（contextvar）标记「这次调用算在谁头上」。
- 智能助手同步和流式对话、办公助手、文件处理和合规报告抽取的视图、多 Agent 任务的 Celery 任务、数字员工运行，入口处都设置 scope。
- 流式生成器在每次 `next()` 时都重新进入 scope，不依赖 contextvar 在多次 yield 之间保持，WSGI 和 ASGI 下都成立。
- scope 同时累计本轮所有调用的 token 和费用，用来回填 AgentLog。

**记账**：路由三个出口（非流式、带工具、流式）成功后记一次，失败记 `failed_calls`。记账本身出错不影响 LLM 调用。
- **流式**：解析 SSE 时，若响应里带 `usage` 就用它。端点 `model_capabilities.stream_usage=true` 时会请求 `stream_options.include_usage`；默认不请求，以免不支持该参数的服务报 400。
- 没有 usage 时按字数估算：中文约 0.7 token/字，其他字符约 4 字符/token，并计入 `estimated_calls`。
- 客户端中途断开（GeneratorExit）也会记账。
- `OllamaClient.generate`（合规报告抽取）用 Ollama 原生的 `prompt_eval_count` / `eval_count` 计量，app 记为 `documents`。

**AgentLog 回填**：同步和流式对话的 `input_tokens` / `output_tokens` / `total_tokens` / `estimated_cost` 改为**本轮所有 LLM 调用的合计**。
- 之前只记最后一次调用，流式为空。
- 「使用统计」页的 token 和成本因此变得完整。

## 4. 拦截与降级

**硬上限（blocked）**
- **智能助手入口**（同步和流式）：先检查状态；blocked 时不进编排，直接回复「今日 AI 额度已用完……明天恢复，或联系管理员调整」，错误类型为 `budget_exceeded`（新增到 `ERROR_KIND_HINTS`）。失败回答不落会话，但写 AgentLog。
- **路由兜底**：每次调用前检查当前 scope 的用户和应用状态，blocked 时抛 `LlmBudgetExceeded`，不发请求。
  - 现有调用方都会捕获异常并降级：抽取器返回 None、意图回退为闲聊、数字员工改用模板。
  - 办公助手、文件处理在视图里把它转成 429，并返回提示。

**软上限（readonly）**
- **写工具**：新增 `BudgetHook`（PRE_EXECUTE，优先级 30，排在限流和确认之前），对需要确认的工具返回 `Reject(error_code="budget_readonly")`。三条执行路径已有的逻辑会直接阻断，并把提示带给用户。
  - 已经生成的确认卡仍可确认：确认本身不调用 LLM。
- **多步复杂任务**：入口把 `task_proposal_allowed` 置为 False，不出任务计划卡；创建 AgentTask 的接口返回 409（`budget_readonly`）。
- **办公文档生成**：智能助手里的 `office_generate` 属于写工具，已被拦下；办公助手的两个生成接口返回 429（`budget_readonly`）。
- 普通查询（只读工具、知识库、闲聊）照常。
- 对话响应里带 `budget: {state, message}`，前端在对话区显示提示条。

## 5. 接口与页面

**用户**
- `GET /api/smart-assistant/budget/me/`：今日状态、用量、上限及来源（个人 / 用户组 / 全员默认），以及所在应用的状态。
- 智能助手页：状态不是 ok 时，在输入框上方显示提示条，内容为已用百分比和受限范围。

**管理员**（仅智能助手管理员）
- `budget/policies/`：增删改查。
  - 全员默认只能改、不能删；
  - 用户组、个人、应用各自唯一；
  - 上限不能为负；软上限比例 1–100。
- `budget/usage/?days=7`：
  - 今日按应用汇总（含状态）；
  - 近 N 天按天趋势；
  - 用量前 20 的用户（含状态和上限来源）；
  - 数字员工用量；
  - 估算调用的占比。
- 控制台「AI 管理 → 预算与用量」（`/control-panel/ai/budget`）：今日概况、趋势、用户排行，以及配置编辑（全员默认、用户组、个人、应用）。

## 6. 测试

- **计量**：
  - 非流式、带工具、流式都会记账；流式有 usage 用 usage，没有就估算；中途断开也记账；
  - 失败记 `failed_calls`；记账出错不影响调用；
  - `OllamaClient` 会记账；
  - 归属正确：用户、数字员工、无 scope。
- **状态**：
  - 上限来源的优先级：个人 > 组（多个组取最宽松）> 默认；0 表示不限；
  - 软、硬阈值；应用状态叠加到用户状态上。
- **拦截**：
  - blocked：入口直接回复并带 `budget_exceeded`；路由兜底抛异常，不发请求；办公助手返回 429。
  - readonly：写工具被拒（三条路径）；复杂任务不出计划卡；创建 AgentTask 返回 409；办公助手返回 429；只读查询正常；已有确认卡仍可确认。
- **AgentLog**：同步和流式都回填本轮合计。
- **接口**：me、policies（权限、唯一性、校验、默认不能删）、usage 汇总。
- **前端**：预算页的渲染和编辑；对话提示条。

## 7. 不做

- 「排队」式降级：超额后排到次日执行。方案里写的是「只读或排队」，本批按已确认的决定做只读 + 停用。
- 按小时或按月的窗口；跨应用的费用预算（货币）上限。本批只做 token 和调用次数，费用只统计不拦截。
- 评估集、发布门禁（以后单独开批次）。
